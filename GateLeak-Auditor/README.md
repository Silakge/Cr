# GateLeak Auditor

GateLeak Auditor 是一个本地运行的 Chrome Manifest V3 扩展，用来审计生成式图像服务是否在最终拒绝之前，已经把图片字节、图片 Blob 或图片能力 URL 交给浏览器。

当前版本：`0.3.1`。本版本新增默认关闭的“保留候选图片”研究模式，并把导出入口提升为结果卡下方醒目的紫色按钮：可把浏览器已收到并经正文验证的栅格图片候选逐条导出，供研究者人工判断是否属于被拒绝的生成任务。

它回答的是客户端信任边界问题，不判断某个角色是否侵权，也不会重新请求 URL、恢复过期链接或绕过平台控制。

## 能检测什么

扩展在用户点击“开始审计”后观察当前标签页：

- HTTP 图片响应及其 MIME、状态、字节数、缓存来源和截断 SHA-256；
- JSON、SSE 和 WebSocket 文本帧中的拒绝语句、图片 URL 字段、任务 ID 和 Base64 图片；
- WebSocket 二进制帧中的常见 PNG、JPEG、GIF、WebP、AVIF 特征；
- 瞬时加入或删除的 `img`、`source`、`video poster`、CSS 背景、`blob:`、`data:` 和 `canvas` 元素；
- 自动检测到的拒绝时刻，以及用户手动标记的拒绝时刻。

最终给出解释性等级：

| 等级 | 含义 |
| --- | --- |
| L0 | 观察到拒绝，但没有客户端图片证据 |
| L1 | 拒绝前只有任务或资产标识符 |
| L2 | 拒绝前出现图片/缩略图 URL，但没有确认图片字节 |
| L3 | 拒绝前出现经网络正文、嵌入数据或浏览器解码确认的图片字节候选 |

L3 仍然是“候选”：研究者必须排除头像、Logo、页面背景等无关图片。时间线中的每条证据都可以勾选“排除”，分类会立即重算。

## 安装

1. 解压发布 ZIP。
2. 在 Chrome 打开 `chrome://extensions`。
3. 打开右上角“开发者模式”。
4. 点击“加载已解压的扩展程序”。
5. 选择包含 `manifest.json` 的 `gateleak-auditor` 文件夹。
6. 建议把 GateLeak Auditor 固定到工具栏。

Chrome 会提示该扩展拥有调试器权限。这是读取响应级网络事件所必需的；扩展只会在你主动点击“开始审计”后附加到当前标签页。

## 使用

1. 打开目标生成式图像页面并等待页面加载稳定。
2. 不要同时打开该标签页的 Chrome DevTools。Chrome 在打开 DevTools 时会终止扩展的调试连接。
3. 点击扩展图标，设置拒绝关键词和图片候选字节阈值，然后点击“开始审计”。默认关键词是“非常抱歉”，多个关键词使用 `|` 分隔。
4. 返回页面，仅提交一次安全、合规的研究测试。
5. 页面显示违规时，扩展通常会自动识别；也可以点击“立即扫描页面”。如果仍未识别，立即按 `Alt+Shift+G`，Mac 上按 `Command+Shift+G`，或者点击“标记违规时刻”。快捷键可在 `chrome://extensions/shortcuts` 中修改。
6. 等待请求结束，重新打开扩展，检查 L0–L3 结论和事件时间线。
7. 排除明显无关的页面图片，然后导出脱敏 JSON。
8. 点击“停止”使扩展立即与标签页分离。

如需人工核验 L3 候选，在开始审计前勾选“保留候选图片（研究模式）”并确认提示。成功保留后，结果卡下方会出现“已保留图片”区域和醒目的紫色导出按钮；对应时间线事件也保留一个导出入口。扩展只保留本次审计期间浏览器已经收到的、经响应正文验证的 PNG/JPEG/WebP/GIF/AVIF 候选；不会重新请求图片 URL。最多保留 3 张，单张不超过 3 MB，总计不超过 5 MB。停止审计后仍可导出；点击“清空”、浏览器重启、扩展重载或更新后删除。

图片导出与“导出脱敏 JSON”彼此独立，JSON 永远不嵌入图片正文。若图片只存在于加密帧、未完成的流或未形成可读取的图片响应中，时间线可能记录 L3，但不会出现导出按钮。

点击开始时页面里已经存在的拒绝关键词会被记录为基线并忽略；只有新增关键词或新 DOM 拒绝节点才作为本次拒绝。为保证图片时序能够归因，每次审计仍应只提交一个生成任务。若检测到多次独立拒绝，扩展会显示 `!` 并要求重新分次测试。

最可靠的 L3 证据组合是：同一个脱敏 URL 指纹既出现成功图片响应，又出现 DOM 图片解码，而且二者都早于拒绝判定。

## 本地自测

在扩展目录运行：

```bash
python3 -m http.server 8000 -d demo
```

打开 `http://localhost:8000`，启动审计，然后分别测试页面中的 L0、L2、L3 按钮。每次测试前清空并重新开始一次审计。

核心分类器测试：

```bash
npm test
```

## 隐私设计

- 不写入请求头、Cookie、Authorization、提示词或响应正文。
- 原始 URL 仅在内存中短暂用于计算指纹；持久状态只保留 origin、文件类型提示和不可逆的短指纹。
- 默认情况下，图片响应正文只用于计算字节数和 SHA-256，随后丢弃。
- 只有用户在开始前显式开启研究模式时，符合条件的候选图片正文才会写入 `chrome.storage.session`；它与审计 JSON 分开保存，有严格数量和大小限制。
- 审计状态保存在 `chrome.storage.session`，浏览器重启、扩展停用或扩展更新后清除。
- 导出的 JSON 仍可能包含目标域名、时间、大小和任务字段名称，公开前应再次审阅。

详见 [PRIVACY.md](PRIVACY.md)。

## 已知限制

- 自动拒绝识别采用启发式规则；手动标记优先于自动时间点。
- 页面可能在应用层加密或封装数据，扩展只能记录无法解释的二进制帧。
- DOM 观察器默认只注入主框架；跨域 iframe 的 DOM 可能不可见，但其网络事件通常仍可观察。
- `canvas` 的创建或尺寸变化不能证明其中绘制了目标图片。
- 浏览器内部页面、Chrome Web Store 和其他禁止调试的页面不能被审计。
- 打开 DevTools 会使 `chrome.debugger` 会话断开；扩展会把本次审计标记为“已中断”。
- “未发现”不是不存在的证明。L0 只能说明当前检测范围内没有客户端证据。

## 研究与披露边界

只测试你有权使用的账户和页面，不绕过访问控制，不阻止删除请求，不重放签名 URL。候选图片仅用于本地归因和人工判读，不应传播。若得到 L3 证据，优先保存脱敏时间线并向服务提供方进行负责任披露；进一步验证 L4（拒绝后仍可访问）应取得明确授权。

## 开发说明

项目无第三方运行时依赖。关键文件：

- `background.js`：CDP 网络观察、响应元数据提取和状态管理；
- `content.js`：只观察 DOM 的 MutationObserver；
- `lib/core.js`：脱敏、文本扫描、候选评分和 L0–L3 分类；
- `popup.*`：控制面板、时间线、排除与导出。
